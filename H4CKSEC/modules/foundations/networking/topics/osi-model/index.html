The OSI Model

Seven-layer reference model for network communication. Layer responsibilities, protocol data units and mapping to real-world protocols.

Beginner 12 min read Updated November 2026

Definition

The Open Systems Interconnection (OSI) model is a conceptual framework that standardizes the functions of a telecommunication or computing system into seven abstraction layers. It was developed by the International Organization for Standardization (ISO) to enable interoperable communication between different systems.

The OSI model is a reference model — it describes what each layer should do, not a specific implementation. Real networks primarily implement the TCP/IP model, but the OSI layers remain the standard vocabulary for discussing networking concepts, troubleshooting and security analysis.

The Seven Layers

Layers are numbered from 1 (bottom, closest to the physical medium) to 7 (top, closest to the user application). Data moves down the stack on the sending host (encapsulation) and up the stack on the receiving host (decapsulation).

Layer 7 — Application

Provides network services directly to end-user applications. This is where protocols that humans interact with live.

  • Examples: HTTP/HTTPS, DNS, SMTP, IMAP, FTP, SSH, SNMP, DHCP (client side)
  • PDU: Data / Message
  • Security relevance: Application-layer attacks (injection, XSS, command injection), application firewalls, API security

Layer 6 — Presentation

Responsible for data translation, encryption/decryption and compression. Ensures that data from the application layer of one system can be read by the application layer of another.

  • Examples: SSL/TLS (often discussed here or at Session), JPEG, ASCII/Unicode conversion, MIME
  • PDU: Data
  • Security relevance: Encryption, certificate validation, encoding attacks

Layer 5 — Session

Establishes, manages and terminates sessions between applications. Handles dialog control (full-duplex, half-duplex) and synchronization.

  • Examples: RPC, NetBIOS, PPTP, SIP session aspects
  • PDU: Data
  • Security relevance: Session hijacking, session fixation, token management

Layer 4 — Transport

Provides end-to-end communication services. Responsible for segmentation, reliability (or lack thereof), flow control and multiplexing via ports.

  • TCP — connection-oriented, reliable, ordered delivery, congestion control
  • UDP — connectionless, unreliable, low overhead, used for DNS, VoIP, streaming
  • PDU: Segment (TCP) / Datagram (UDP)
  • Security relevance: Port scanning, TCP sequence prediction, SYN floods, UDP amplification

Layer 3 — Network

Handles logical addressing and routing of packets between different networks. The Internet Protocol (IP) is the dominant protocol at this layer.

  • Examples: IPv4, IPv6, ICMP, IGMP, IPSec, OSPF, BGP
  • PDU: Packet
  • Devices: Routers, Layer-3 switches
  • Security relevance: IP spoofing, routing attacks, ICMP abuse, firewall rules based on IP/port

Layer 2 — Data Link

Provides node-to-node delivery on the same network segment. Handles framing, physical addressing (MAC), error detection and media access control.

  • Examples: Ethernet (IEEE 802.3), Wi-Fi (802.11), PPP, ARP (often placed at the boundary of L2/L3)
  • PDU: Frame
  • Devices: Switches, bridges, NICs
  • Security relevance: MAC spoofing, ARP spoofing/poisoning, VLAN hopping, CAM table overflow

Layer 1 — Physical

Defines the electrical, optical and mechanical characteristics of the medium. Transmits raw bit streams.

  • Examples: Copper cables (Cat5e/6), fiber, radio frequencies, hubs, repeaters
  • PDU: Bits
  • Security relevance: Physical access, cable taps, jamming, hardware implants

Encapsulation & PDUs

As data travels down the stack, each layer adds its own header (and sometimes trailer). The unit of data at each layer is called a Protocol Data Unit (PDU):

  • Application / Presentation / Session → Data
  • Transport → Segment (TCP) or Datagram (UDP)
  • Network → Packet
  • Data Link → Frame
  • Physical → Bits
Tip When analyzing packet captures (Wireshark, tcpdump), remember that what you see is the fully encapsulated frame. Filters and dissection views help you inspect individual layers.

Security Implications

Understanding the OSI model helps place attacks and defenses in the correct context:

  • L7: WAF, input validation, secure coding, application logging
  • L4: Stateful firewalls, SYN cookies, rate limiting, port control
  • L3: ACLs, anti-spoofing (uRPF), routing security (RPKI for BGP)
  • L2: Port security, Dynamic ARP Inspection, DHCP snooping, 802.1X
  • L1: Physical access controls, cable management, TEMPEST considerations
Security note Many real-world attacks cross layers. A successful phishing email (L7 social engineering) can lead to credential theft that enables lateral movement at L3/L4. Always reason about the full path.

Troubleshooting with OSI

A common methodical approach is to start at Layer 1 and work upward (or start at the symptom and work down):

  1. Physical: Is the link up? Cable, power, interface status?
  2. Data Link: MAC addresses correct? ARP resolution working? Switch port errors?
  3. Network: Correct IP, gateway, routes? Can you ping the next hop?
  4. Transport: Is the port open? Firewall blocking? TCP handshake completing?
  5. Application: Correct URL, DNS resolution, application logs, certificates?
bash
# Quick layer-oriented checks (Linux)
ip link show          # L1/L2 interface state
ip addr show          # L3 addressing
ip route              # L3 routing table
ss -tuln              # L4 listening sockets
dig +short example.com  # L7 DNS
curl -v https://example.com  # L7 HTTP(S)
